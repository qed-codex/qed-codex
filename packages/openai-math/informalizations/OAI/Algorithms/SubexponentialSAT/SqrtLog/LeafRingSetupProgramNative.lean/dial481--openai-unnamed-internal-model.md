### `idempotentCall`

 The idempotent producer is called with a fresh private workspace.  It
computes its own scalar preparation from binary t; no coefficient array or
arithmetic oracle is passed to it. 

 The fixed executable preparation pipeline.  Its input is the actual
numerical bank emitted by `LeafParametersProgram`; no field polynomial,
modulus, multiplication table, nodes, or idempotent coefficients are inputs.
The stage-by-stage execution theorem is separate from this code definition.


 Arithmetic consumers use the same bytes generated by the preceding
stages.  These are structural handoff lemmas; the complete production
trace must establish `NativeBytes` before invoking them. 

### `NativeBytes.nativeReady`

 Setup supplies the physical shared scalar/extension-ring context.
The consumer still pays its own entry copies into ports5,10 and104. 

### `unary_eval_stacks`

 A convenient stack-only form of the paid unary-conversion theorem. 

### `unaryPlan_eval`

 A finite list of counter conversions is one measured program.  Its
conclusion identifies every stack, including preserved parameter words. 

### `searchAndPad_eval`

 The field polynomial and its lifted bytes are produced by one real
search/copy/padding execution.  The clearing cost of the search's old width
scratch is bounded by the actual search trace. 

### `installIndexed`

 An explicit finite-tape form of a framed call's output. This is a proof
normal form; executable code remains the actual relocated program. 

### `initial_clear_parameter_projection`

 The first paid cleanup preserves the complete generated numeric bank. 

### `final_clear_private`

 Final cleanup restores every setup-private tape, independently of the
large temporary words that its generators may have produced. 

### `coreCommand`

 The arithmetic core uses the generated scalar cache, searches for the
extension polynomial, and constructs its multiplication table. 

### `CoreInput`

 These are input tape conditions, not supplied mathematical ring data.
The only numerical words needed by this phase are binary precision and
unary dimension.  The outer setup establishes the empty tapes by clearing. 

### `CoreOutput.reindex`

 This core result has no modulus, irreducible polynomial, scalar cache,
or table premise.  All four objects are generated by the executed code. 

### `serializationCall_eval`

 The serializing arithmetic runs on the actual parameter-bank tapes;
it computes qE-2 and 2t rather than receiving those unary counters. 

### `unaryCopyBound_le`

 A coarse input-dependent bound for each preserving unary conversion. 

### `numericPlan_cost_le`

 For the fixed five-counter plan, no destination overlaps a source. 

### `numberPhase`

 The prelude preserves the numerical bank until the last dependent
counter and node-count word have been consumed. 

### `numberPhase_eval`

 Actual generated counters and a one-word scalar-service input.  The
bounds concern finite bank values and tape lengths; no arithmetic context
is assumed. 

### `coreFromBankCommand`

 An actual prefix of the complete setup: generated numeric metadata is
serialized and then used by the scalar/extension-ring construction. 

### `buildConstant`

 The seed is copied from a retained scalar master before the actual
literal-vector constructor consumes it. 

### `constantBatch`

 Generate the three dynamic-dimension constant vectors on their native
consumer ports.  Each scalar master remains available throughout. 

### `copyPlan`

 Finite staged cache copies; this is executable code, including clearing
reused destinations and the preserving copy loops. 

### `nodesCall_produces`

 The node generator reads only its scalar-width zero word, binary count,
and unary dimension.  All other global metadata remains framed. 

### `nodeWords_flat_length`

 The length used by all node-stream copies follows from the actually
constructed fixed-width words. 

### `eval_stack_length_le`

 A bound on actual tape lengths follows from the compiled instruction
trace; it is not a cost annotation on an abstract computation. 

### `constantStartPorts`

 Explicit clearing makes the constant constructor independent of the
search/table producers' discarded work tapes. 

### `idempotentPhase_eval`

 A fresh private Newton execution produces the persistent coefficient
master.  Its modulus/cache witnesses are generated, not supplied inputs. 

### `nodesPhase_eval`

 Both flat nodes and their framed master are produced and retained. The
flat list is copied before framing consumes it, and restored afterwards. 

### `RingCaches`

 Persistent ring data. The private scalar masters are deliberately not
part of this contract: later private Newton preparation may reuse them. 

### `RingCaches.zero_bytes`

 The generated canonical scalar zero has the literal bytes required by
the native CRT/readback interface. No additional cache premise is needed. 

### `RingCaches.fullZero_model`

 The dynamic constant constructor emits the model's exact zero code. 

### `RingCaches.fullOne_model`

 The dynamic constant constructor also emits the exact model one code. 

### `finalDiscard`

 The final cleanup produces the exact shared scalar and polynomial
contexts consumed by the existing native arithmetic programs. 

### `collector_not_touched`

 All collector tapes lie outside every setup write set. 

### `producerCommand`

 The assembled producer uses the proved clearing boundaries between
services, rather than depending on unused values in prior work tapes. 

### `producerBudget`

 Stage costs are composed with actual tape growth. All stage counts are
fixed polynomials except the explicit, independently bounded search and
Newton budgets. 

### `producerCommand_eval`

 Complete actual preparation from the physically present finite numeric
bank. No modulus, polynomial, table, scalar cache, node list, idempotent
array, or arithmetic readiness predicate occurs among the premises. 

### `command`

 Public names refer to the fully assembled, measured producer. 

### `producerProgram_runs`

 The fixed finite instruction table realizes the full producer contract. 

### `producerProgram_lifted`

 The outer leaf uses the same actual producer in its larger fixed
ambient. Parser/branch registers and the collector's tapes are retained.
